# 评分维度自评

> 按「AI 技术深度 35% / 创新性 25% / 前端工程质量 10% / 实用性 10% / 用户体验 10% / 社会价值与商业潜力 10%」逐项对照，
> 每条给出**可以现场验证的证据**，以及我自己认为还不够的地方。自评不吹分，只列事实。

## 一、AI 技术深度（35%）

| 核心考察点 | 证据 | 位置 |
|---|---|---|
| 应用深度 | 不是单次问答，而是六 Agent 固定分工的生产流水线：清洗 → 切分 → 抽决议 → 抽待办 → 独立复核 → 成文；decider 与 planner 并行 | `apps/api/app/core/pipeline.py` |
| 集成质量 | 结构化输出契约 `call_json`：剥围栏、截首个 `{}`、失败自愈重试、`finish_reason=length` 时预算翻倍；异常统一降级到 Mock，界面不崩 | `apps/api/app/core/structured.py` |
| 技术选型有依据 | 同一 decider 任务跑四组对照：flash+关思考 3.9s/7 条、flash+开思考 7.7s/7 条、pro+关思考 6.4s/6 条、**pro+开思考 49.5s/0 条**（预算全被思维链吃掉）。据此把抽取类 Agent 全切快模型+关思考，端到端 410.3s → 31.5s | `scripts/bench_reasoning.py`、`data/bench_reasoning.json` |
| 幻觉治理 | 结论强制携带原文引文，落库前用 difflib 回查转写原文，重合度 <0.55 直接丢弃；丢弃后无证据的条目不硬凑，降级为「未决」并入 open_question | `core/pipeline.py: validate_evidence` |
| 检索质量 | BM25 ⊕ 向量召回 → RRF 融合 → LLM 精排；引用强弱判定改用「覆盖率 + 对比度 + 数字硬约束」，12 题 hit@6 = 100%，引用支撑 26/36 = 72.2% | `core/rag.py`、`scripts/eval_quality.py`、`data/eval_report.md` |
| 工程化 | 语义缓存（阈值 0.95）、四档模型路由、PII 脱敏网关、token 预算、每次调用记账（token/耗时/成本/缓存命中） | `core/cache.py`、`core/routing.py`、`core/guard.py`、`core/trace.py` |
| 自测 | 20 条单测（diff 重建、补丁定位、工期模型、引用校验、脱敏），无网络无数据库 | `apps/api/tests/test_core.py` |

**还不够的**：没有做微调与本地小模型量化对比；评测集 12 题偏小，只能说明趋势，不能说明分布。

## 二、创新性（25%）

**选题创新**：市面上 AI 会议工具解决「把话变成字」，我们解决「字能不能被信任」——把「证据」做成数据模型的第一等公民（每条决议/待办都挂 evidence），并让「无证据」成为合法的输出状态。

**模式创新**
1. **会议 → 任务 → 周报闭环**：待办一键转看板卡，带负责人、截止日与 P50/P90 工期区间；周报正文按「任务指纹」缓存，数据不变不重复花钱。
2. **补丁级写作**：不让模型重写整篇，要求输出 `{op, target, new_text, reason}` 补丁，后端定位应用再算行级 diff，用户逐条勾选。23/23 补丁定位成功。
3. **Critic 差异化处置**：复核 Agent 判「结论」不合格就删，判「待办」不合格只降置信度不删——结论判错是失准，待办删掉是失职。

**交互创新**
4. **Agent Trace 产品化**：把六步执行链、每步 token/耗时/证据数做成可展开页面，用户能看到「这句话是谁、花多久、依据几条」产出的。
5. **引用强弱标注**：回答里区分「强支撑（可直接引用）」与「弱支撑（可能是模型自己的总结）」，比单纯标来源更有决策价值。
6. **问答先给检索、再给正文**：SSE 先推召回片段，用户立刻知道「它在查什么」，而不是对着转圈等七秒。

## 三、前端工程质量（10%）

- 组件化：12 个页面 + 9 个通用组件 + 3 个图表组件（原生 SVG，无图表库）+ 4 个 lib 模块；
- 类型：全量 TS strict，接口类型集中在 `src/types.ts`，与后端返回逐字段对齐（曾因 `StyleProfile` 字段错位导致白屏，已按真实响应重写契约）；
- 状态：自研 `useAsync / usePoll / useDebounced`，不引状态库与请求库，包体 index 133.79kB + react 164.85kB；
- 性能：路由级页面拆分、静态资源长缓存、会议详情用轮询而非长连接、长列表不渲染不可见项；
- 一致性：全部颜色/圆角/阴影走 Tailwind token，表格、卡片、按钮各自一个 `@layer components` 类。

**还不够的**：没有做 Lighthouse 报告与首屏性能预算；没有前端单测（只有类型检查 + 构建门禁）。

## 四、实用性（10%）

- 真实场景：目标用户是 5–50 人的产品/研发团队，每周 3–8 场会，会后整理平均 40 分钟/场；
- 现在能省：一场 12 段转写的会 31.5 秒出纪要，成本约 $0.005；
- 不是 demo 玩具：演示数据 3 场会议 / 26 段转写 / 11 条决议 / 16 条任务；导出 Markdown 与 Word（宋体 10.5、表格带样式）可直接进周报；
- 可落地：Docker Compose 一条命令起服务，SQLite 单文件，无外部依赖服务。

**还不够的**：没有接企业微信/飞书日历，真实团队接入还要一步同步；没有做多租户计费。

## 五、用户体验（10%）

- 首屏：登录页左侧直接讲清产品价值与三个关键数字，右侧预填评审账号，评委不用找账号；
- 反馈：所有异步都有骨架屏/加载态/空状态/错误态四种形态；会议分析中显示进度轮询而不是假装完成；
- 可理解：证据链页签点引文可跳到原文时间点；Agent Trace 显示中文 Agent 名与一句话职责；
- 容错：模型失败降级 Mock、周报无正文时给「先生成」按钮而不是白屏（这条是踩坑后补的）。

**还不够的**：移动端只做了响应式收缩，看板的拖拽在触屏上体验一般。

## 六、社会价值与商业潜力（10%）

- 社会价值：中小团队最贵的是「信息搬运」的时间；把会议沉淀成可检索、可追责的资产，减少「会开完就散了」的浪费。PII 脱敏网关保证身份证/银行卡/手机/邮箱不出内网，符合国内合规直觉。
- 商业潜力：单场成本 $0.005，按团队 20 场/月计约 ¥7/月模型成本，具备按席位订阅的空间；可延伸出「会议质量分」「项目健康度」等增值模块。
- 可持续性：模型层可插拔（DeepSeek / OpenAI 兼容 / Ollama 本地），不绑定单一供应商；本地模型档位面向数据不出内网的客户。

**还不够的**：没有真实客户验证与付费转化数据，商业判断目前是推理而非实证。

## 现场演示建议（3 分钟）

1. `/dashboard` 四个 KPI + 14 天趋势 → 「数据来自真实运行记录」；
2. `/meetings/1` → 证据链页签，点开引文看原文时间点 → 「没有证据的条目会降级成未决」；
